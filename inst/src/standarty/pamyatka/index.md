# Памятка: как мы работаем с инструкциями

## Идея в трёх строках

- Инструкции пишутся как код: **частями**. Часть написана один раз, в других местах её только упоминают.
- Скрипт **собирает** из частей готовый текст и **проверяет**, что ничего не сломано.
- Исходники правим руками, собранное — никогда.

## Где что лежит

| Папка | Что там | Править руками |
|---|---|---|
| `inst/src/md-kod/tio/` | инструкции | да |
| `inst/src/md-kod/zna/` | знания | да |
| `inst/src/md-kod/um/` | умения | да |
| `inst/src/md-kod/lis/` | листы таблиц, по одной части на лист: `index.md`, `stolbtsy.yaml` (руками), `struktura.yaml` (из таблицы); реестр `listy.yaml` | да, кроме `struktura.yaml` |
| `inst/src/md-kod/pro/` | процессы: `reglament.yaml` — как записано (руками не править), `protsess.yaml` — кто что делает | да, кроме `reglament.yaml` |
| `inst/src/md-kod/reg/` | реестр: `ter.yaml` — термины, `rol.yaml` — должности, `oby.yaml` — обязанности, `mes.yaml` — места работы, `art.yaml` — что передаётся, `res.yaml` — рабочие ссылки | да |
| `inst/src/standarty/` | формат, шаблон, правила, эта памятка | да |
| `full.yaml` в папке инструкции | что включить в её полный документ | да |
| `inst/src/full/` | описания сводных полных документов | да |
| `inst/src/skripty/` | сборщик `sobrat.py`, `slugify.sh` | да |
| `inst/md-out/` | собранный вид «репозиторий», лежит в Git | **нет** — пересобирается |
| `inst/md-full-out/` | полные документы, в Git не идут | **нет** |
| `inst/docx/` | полные документы в `.docx`, в Git не идут | **нет** |
| `inst/PLAN.md` | что не написано и что проверить | да |
| `raw/` | сырое: первая и вторая попытка | нет |

## Команды

| Команда | Зачем |
|---|---|
| `make inst` | собрать `inst/md-out` |
| `make test` | проверить всё; должно кончиться словами `orb-work: ok` |
| `make podpisi` | редактор подписей на снимках; с ноутбука: `ssh -L 8765:localhost:8765 ag12`, потом в браузере http://localhost:8765 |
| `make full F=tio.skr-zapusk-triggerov` | собрать короткий и полный md инструкции в `inst/md-full-out/tio/` |
| `make inst OUT=папка` | собрать в другую папку (версия, выгрузка) |
| `make docx F=tio.skr-zapusk-triggerov` | собрать и сразу два `.docx` с датой: короткий и `-full` — в `inst/docx/tio/` |
| `make reglament X=raw/…/….xlsx` | пересобрать шаги процессов из регламента «Распределение задач» |
| `make mermaid` | проверить схемы Mermaid настоящим mermaid-cli (по желанию; ставится `make mermaid-setup`) |
| `make reglament-xlsx` | книга регламента для Google Таблиц — в `raw/` (шаги и справочники) |
| `make listy` | устройство листов из таблиц в `raw/` → `lis/*/struktura.yaml`, заготовки новых листов |

Проверка и сборка идут без Docker, за секунды. Нужны `python3` и PyYAML. Docker нужен только для `make docx`.

## Что читать и что пересылать

- **`md-out`** — для нас: быстро пролистать и вспомнить. Умения в инструкциях там — карточки со ссылками.
- **Полный документ** — для сотрудников: один файл, всё вставлено. Собирать заново перед каждой отправкой — старый файл устаревает.

## Как добавить часть

1. Придумать короткое русское название и получить имя папки: `bash inst/src/skripty/slugify.sh Цвета адресов`; впереди поставить префикс темы (`tab`, `tov`, `ras`, `skr`, `lis`); для листа — префикс контура (`k0`…`k4`).
2. Создать папку в нужном разделе: `inst/src/md-kod/zna/ras-tsveta-adresov/`, в ней `index.md` и, если нужно, `imgs/`.
3. Написать шапку: `title`, `kratko`, `polno`, `status`, `nuzhno`. Для инструкции взять шаблон.
4. Статус `проверить` или `заглушка` — добавить строку с именем части в `inst/PLAN.md`, иначе проверка не пропустит.
5. `make inst`, потом `make test`.

## Как упомянуть часть

| Пишем | Получаем |
|---|---|
| `[[zna.tab-nmts]]` в предложении | короткое имя ссылкой (поле `kratko`) |
| `[[zna.tab-nmts]]` отдельной строкой или пунктом списка | карточка: название и описание (поле `polno`) |
| `[[zna.tab-nmts\|свой текст]]` | ссылка со своим текстом |
| `[[zna.tab-nmts:kratko]]`, `[[zna.tab-nmts:polno]]` | короткое имя или карточка — явно |
| `[[zna.tab-nmts:tekst]]` отдельной строкой | в полном документе — текст части целиком; в `md-out` — карточка |
| `[[ter.kp]]`, `[[rol.zakupka]]`, `[[oby.oplata]]`, `[[mes.lis-5-5]]`, `[[res.shablon-tablitsy]]` | термин, должность, обязанность, место работы и рабочая ссылка из реестра |

Упомянул часть — впиши её имя в `nuzhno` в шапке.

## Если проверка упала

| Сообщение | Что сделать |
|---|---|
| упомянута часть, но её нет в nuzhno | дописать имя в `nuzhno` |
| упомянута часть, которой нет | исправить имя или создать заглушку |
| в реестре нет записи | добавить запись в `reg/ter.yaml` или `reg/res.yaml` |
| нет снимка | положить файл в `imgs/` или убрать ссылку |
| части нет в inst/PLAN.md | добавить строку в план |
| inst/md-out устарел | `make inst` и закоммитить |

## Как сдаётся работа

1. Ветка от свежего `main`: `task/<индекс>-<суть>`.
2. Правки в `inst/src`, затем `make inst` и `make test`.
3. Коммит исходников вместе с пересобранным `inst/md-out`, пуш, PR в `main` с отчётом.
4. Вливает директор.
