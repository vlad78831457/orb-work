# Формат: инструкции из частей

Инструкция пишется как код: частями. Часть написана один раз, в других местах её только упоминают ссылкой.
Сборщик проверяет части и собирает из них готовый документ.

## Часть

Часть — папка `inst/src/<имя>/` с файлом `index.md` и снимками в `imgs/`. В начале файла — шапка:

```
---
id: instructions.calculation-specialist
title: "Инструкция по работе с таблицами для специалиста по расчёту"
requires:
  - knowledge.nmts
  - skills.insert-only-values
---
```

| Поле | Что это |
|---|---|
| `id` | имя части: `instructions.…` — инструкция, `knowledge.…` — знание, `skills.…` — умение |
| `title` | название для людей |
| `requires` | имена частей, от которых эта зависит; если не зависит — `requires: []` |

## Упоминание

Чтобы сослаться на другую часть, ставится обычная ссылка Markdown: в квадратных скобках — текст, в круглых — путь к файлу
`index.md` этой части, например `../znanie-nmts/index.md`. Живой пример — список «Знания / Умения / Инструкции» и шаги
в [инструкции для специалиста по расчёту](src/instr-dlya-spetsialista-po-raschetu/index.md).

Текст ссылки — любой. Каждая упомянутая часть должна быть в `requires`.

## Два вида

- **Репозиторий** — это сами файлы `inst/src/`: на GitHub ссылки между частями работают как есть, собирать ничего не нужно.
- **Полный** — `make inst` кладёт в `inst/dist/full/` один файл на инструкцию: её текст, а ниже — все части, от которых она зависит, каждая один раз. Ссылки на части ведут внутрь этого же файла, поэтому не ломаются при переносе в Google Документ.

## Проверка

`make test` и `make inst` останавливаются с ошибкой, если:

- в `requires` названа часть, которой нет;
- в тексте упомянута часть, которой нет в `requires`;
- ссылка ведёт на файл, который не является частью;
- нет снимка, на который ссылается текст;
- зависимости замкнуты в круг;
- у части нет шапки, `id` или `title`, или `id` занят.

Предупреждение без остановки: часть есть в `requires`, но не упомянута; ссылка `#метка` ведёт в никуда.
