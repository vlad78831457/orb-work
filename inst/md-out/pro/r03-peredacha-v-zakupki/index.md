# Передача в закупки

Процесс регламента «Распределение задач» (лист «10.10.2026 Версия К»), в регламенте — «ПЕРЕДАЧА В ЗАКУПКИ». Контур 2.
Как читать схемы и что значат обязанности — [обзор процессов](../../pro/obzor/index.md).

Шаги «как записано» — `reglament.yaml` (собран скриптом из регламента), наше толкование — `protsess.yaml`. Ниже всё собрано из них.

## Дорожки по должностям

Вертикальная дорожка — должность, которую мы предполагаем; заметка — шаг в её дорожке; стрелка — работа переходит к другой должности (ставит задачу или делает следующий шаг).

```mermaid
sequenceDiagram
  participant r_prodazhi as Менеджер по продажам
  participant r_proekt as Менеджер проекта
  participant r_zakupka as Закупщик
  Note over r_prodazhi: 0. Вход в процесс #quot;Передача в<br/>Закупки#quot;
  r_prodazhi->>r_proekt: Решение передать в закупки
  Note over r_proekt: 1. Постановка задачи на Передачу в<br/>закупки
  Note over r_proekt: 2. Дополнить шаблоны подзадач
  Note over r_proekt: 3. Выполнить подзадачу #quot; Заполнить<br/>лист 5-0#quot;
  Note over r_proekt: 4. Выполнить подзадачу #quot;Проверить<br/>комплектность передачи проекта в<br/>закупку#quot;
  Note over r_proekt: 5. Выполнить подзадачу #quot;Поставить<br/>задачу на закупку#quot;
  r_proekt->>r_zakupka: Задача «Закупка»
  Note over r_zakupka: 6. Выполнить подзадачу #quot;Принять<br/>задачу на закупку#quot;
  r_zakupka-->>r_proekt: дальше
  Note over r_proekt: 7. Возобновление Закупок по<br/>проекту (в случае невыполнения<br/>поставок контрагентами, необхо…
```

## Как в регламенте

Дорожки — столбцы регламента с основным исполнителем; шаги — по порядку. Пунктир — шаг без исполнителя.

```mermaid
flowchart TB
  subgraph c_H["H Менеджер"]
    s_pz_0["0. Вход в процесс<br/>#quot;Передача в Закупки#quot;"]
    s_pz_1["1. Постановка задачи на<br/>Передачу в закупки"]
    s_pz_2["2. Дополнить шаблоны<br/>подзадач"]
    s_pz_3["3. Выполнить подзадачу #quot;<br/>Заполнить лист 5-0#quot;"]
    s_pz_4["4. Выполнить подзадачу<br/>#quot;Проверить комплектность<br/>передачи проекта в за…"]
    s_pz_5["5. Выполнить подзадачу<br/>#quot;Поставить задачу на<br/>закупку#quot;"]
    s_pz_6["6. Выполнить подзадачу<br/>#quot;Принять задачу на<br/>закупку#quot;"]
    s_pz_7["7. Возобновление Закупок<br/>по проекту (в случае<br/>невыполнения поставок к…"]
  end
  s_pz_0 --> s_pz_1
  s_pz_1 --> s_pz_2
  s_pz_2 --> s_pz_3
  s_pz_3 --> s_pz_4
  s_pz_4 --> s_pz_5
  s_pz_5 --> s_pz_6
  s_pz_6 --> s_pz_7
```

| № | Шаг | H Менеджер | I ТС (эксперт) |

| 0 | Вход в процесс "Передача в Закупки" | И |  |
| 1 | Постановка задачи на Передачу в закупки | И |  |
| 2 | Дополнить шаблоны подзадач | И |  |
| 3 | Выполнить подзадачу " Заполнить лист 5-0" | И | С |
| 4 | Выполнить подзадачу "Проверить комплектность передачи проекта в закупку" | И |  |
| 5 | Выполнить подзадачу "Поставить задачу на закупку" | И |  |
| 6 | Выполнить подзадачу "Принять задачу на закупку" | И |  |
| 7 | Возобновление Закупок по проекту (в случае невыполнения поставок контрагентами, необходимости дозакупить что-либо и т.д.) | И |  |

И — исполнитель, С — соисполнитель, Сг — согласование, У — информируемый, В — владелец процесса.

## По обязанностям

Дорожки — должности, которые мы предполагаем; узлы — обязанности. Сплошная стрелка — ставит задачу или передаёт результат, пунктир — следит или согласует; стрелка без подписи — дальше по порядку.

```mermaid
flowchart TB
  subgraph r_prodazhi["Менеджер по продажам"]
    o_reshenie_peredachi("Решающий передать проект в<br/>закупки")
  end
  subgraph r_proekt["Менеджер проекта"]
    o_peredacha_v_zakupku("Передающий проект в<br/>закупку")
    o_list_5_0("Фиксирующий задание на<br/>закупку (лист 5-0)")
    o_proverka_komplektnosti("Проверяющий комплектность<br/>передачи в закупку")
    o_postanovka_zakupki("Ставящий задачу на закупку")
  end
  subgraph r_zakupka["Закупщик"]
    o_prinyatie_zakupki("Принимающий задачу на<br/>закупку")
  end
  o_postanovka_zakupki -->|"ставит"| o_prinyatie_zakupki
  o_reshenie_peredachi --> o_peredacha_v_zakupku
  o_peredacha_v_zakupku --> o_list_5_0
  o_list_5_0 --> o_proverka_komplektnosti
  o_proverka_komplektnosti --> o_postanovka_zakupki
```
